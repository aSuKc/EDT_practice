## 3. Предмет разработки и бизнес требования (User Story) – согласовывается Заявителем

### Цель разработки:

Какую задачу решаем: на ордерных складах материально ответственное лицо (МОЛ) должно определяться однозначно и централизованно, без ручного ввода в карточке каждого склада.

Для чего (зачем) решаем задачу: исключить ошибки и расхождения при указании МОЛ на ордерных складах, убрать возможность случайной подмены ответственного лица вручную, сократить время на заведение и изменение карточек складов.

### Бизнес(функциональные)-требования:

1. В системе должна появиться настройка, в которой администратор указывает одного конкретного пользователя — МОЛ для ордерных складов.
2. При установке в карточке склада признака «Ордерный» = Да в поле «Ответственный МОЛ» должен автоматически подставляться пользователь из настройки.
3. Для склада с признаком «Ордерный» = Да поле «Ответственный МОЛ» должно быть недоступно для ручного редактирования.
4. Для склада с признаком «Ордерный» = Нет поведение не меняется: МОЛ указывается вручную.

### Критерии-приёмки (ожидаемый функционал):

1. Настройка «МОЛ для ордерных складов» существует в системе, доступна для заполнения и хранит ссылку на пользователя информационной базы.
2. При включении флага «Ордерный» в карточке склада поле «Ответственный МОЛ» заполняется значением из настройки без дополнительных действий пользователя.
3. При включённом флаге «Ордерный» поле «Ответственный МОЛ» недоступно для ввода и выбора значения; при выключенном — доступно.
4. Значение МОЛ на ордерном складе не может быть изменено в обход карточки: при любой записи элемента с флагом «Ордерный» = Да в поле записывается значение из настройки.
5. Для склада с флагом «Ордерный» = Нет значение МОЛ сохраняется таким, каким его указал пользователь.

### Предлагаемый функционал:

В расширении создаётся настройка (константа), в которой администратор выбирает пользователя — единого МОЛ для всех ордерных складов. В карточке склада при включении признака «Ордерный» поле «Ответственный МОЛ» автоматически заполняется этим пользователем и становится недоступным для редактирования; при выключении признака поле снова становится доступным для ручного заполнения.

Дополнительно: в справочнике складов тип реквизита «Ответственный МОЛ» меняется с физического лица на пользователя информационной базы, чтобы МОЛ на ордерном складе совпадал с учётной записью, под которой работают кладовщики.

### AS IS

Справочник «Склады» ведётся в расширении. У элемента справочника есть признаки «Ордерный» (Булево) и «Ответственный МОЛ». Реквизит «Ответственный МОЛ» имеет тип «физическое лицо» и заполняется вручную при заведении и изменении карточки склада.

Участники процесса: администратор/ответственный за ведение справочника складов.

Проблемы текущего состояния:

1. На каждом ордерном складе МОЛ указывается вручную, значение может отличаться от склада к складу.
2. Возможна случайная подмена МОЛ при редактировании карточки — ордерный склад остаётся с неверным ответственным лицом.
3. Тип реквизита «физическое лицо» не связан с учётной записью пользователя, из-за чего МОЛ на складе и фактический пользователь системы могут расходиться.

Ограничения: изменение выполняется только в расширении GadjetON_master.РасчетЦены; типовая конфигурация не изменяется.

### TO BE

Новый процесс:

1. Администратор один раз заполняет настройку «МОЛ для ордерных складов», выбрав пользователя информационной базы.
2. При заведении или изменении карточки склада и включении флага «Ордерный» система автоматически подставляет МОЛ из настройки.
3. Поле «Ответственный МОЛ» на ордерном складе заблокировано для ручного ввода; изменить значение можно только через настройку.
4. При записи ордерного склада любым способом (в том числе программно и при загрузке данных) значение МОЛ приводится к значению настройки.

Участники: администратор (заполняет настройку), ответственный за ведение справочника складов (ведёт карточки складов).

Новые объекты системы: константа «МОЛ для ордерных складов»; доработанные объекты: справочник «Склады» (тип реквизита «Ответственный МОЛ», форма элемента, правила заполнения при записи).

Нефункциональные требования: доработка выполняется исключительно средствами расширения конфигурации; изменение типа реквизита «Ответственный МОЛ» требует миграции существующих значений (см. раздел 8).

Критерии успешной реализации: см. «Критерии-приёмки».

## 8. Настройки системы, используемые разработкой

1. **Константа «МОЛ для ордерных складов» (РЦ_МОЛ_ОрдерныйСклад).**
   Место заполнения: раздел «Операции» → «Константы» → «МОЛ для ордерных складов» (либо через форму констант в интерфейсе администратора).
   Значение: пользователь информационной базы, который должен указываться как МОЛ на всех ордерных складах. Значение обязательно к заполнению — иначе реквизит «Ответственный МОЛ» на ордерных складах будет оставаться пустым.

2. **Признак «Ордерный» в карточке склада.**
   Место заполнения: карточка элемента справочника «Склады».
   Значение: Да — для складов, работающих по ордерной схеме (МОЛ подставляется автоматически и блокируется); Нет — для остальных складов (МОЛ указывается вручную).

3. **Миграция данных при изменении типа реквизита «Ответственный МОЛ».**
   Тип реквизита изменяется со «СправочникСсылка.ФизическиеЛица» на «СправочникСсылка.Пользователи». Перед обновлением конфигурации базы данных необходимо зафиксировать перечень складов, у которых реквизит «Ответственный МОЛ» заполнен, и после обновления заполнить его заново — значения прежнего типа не переносятся автоматически. Для складов с признаком «Ордерный» = Да значение проставляется автоматически из константы при первой записи; для складов с «Ордерный» = Нет значение указывается вручную.

| 4 | Сохранение ручного заполнения МОЛ для неордерного склада | Пользователь с полными правами | Справочники → Склады → карточка склада с «Ордерный» = Нет | Указать в поле «Ответственный МОЛ» произвольного пользователя, записать элемент, переоткрыть карточку | Поле доступно для редактирования; после записи и повторного открытия в поле отображается указанный пользователь |
| 5 | Смена МОЛ при снятии признака «Ордерный» | Пользователь с полными правами | Справочники → Склады → карточка ордерного склада | Снять флажок «Ордерный» | Поле «Ответственный МОЛ» становится доступным для редактирования, текущее значение сохраняется |
| 6 | Контроль значения при записи в обход формы | Пользователь с полными правами | Справочники → Склады → список складов | Изменить ордерный склад через список (или выполнить групповую обработку записи элемента с флагом «Ордерный» = Да) | После записи в поле «Ответственный МОЛ» находится пользователь из константы, даже если до записи значение было иным |
